60 · เป่ายิงฉุบที่ผู้เล่นชนะทุกตา

เขียนกฎเลือกท่าที่แพ้ผู้เล่น แล้วตรวจครบทั้งสามท่า

ดาวน์โหลด main.wbas

เป้าหมายและขอบเขต

เกมเป่ายิงฉุบปกติให้คอมพิวเตอร์เลือกท่าโดยไม่รู้คำตอบของผู้เล่น แต่รุ่นนี้ตั้งใจกำหนดให้ผู้เล่นชนะทุกตา เครื่องจึงดูท่าผู้เล่น ก่อน แล้วเลือกท่าที่แพ้: หินชนะกรรไกร กระดาษชนะหิน กรรไกรชนะกระดาษ บทนี้รันสามตาจำลองให้ครบทุกทางของกฎ ผลแน่นอนและใช้ตรวจความถูกต้องของตารางความสัมพันธ์ได้โดยไม่ต้องมีการสุ่มหรือรอ input

เตรียมและรัน

ดาวน์โหลด main.wbas เปิดเทอร์มินัลในโฟลเดอร์นั้น บนเครื่องพัฒนาที่มี wb และ native SDK/runtime คู่กัน:

wb check main.wbas --json
wb run main.wbas

run คอมไพล์ ลิงก์ แล้วรัน ผู้สร้าง wb จาก checkout ผลิตภัณฑ์ใช้ cargo build --workspace --locked ที่รากคลังนั้นก่อน หลักฐานตัวอย่างนี้ใช้ compiler 2614b37 ส่วน compiler 0.0.2 ที่รวมใน main แล้วมี wb build สำหรับ project .wproj พร้อม debug/release; ไม่รับ standalone .wbas แพ็กทดลองมีเครื่องมือ link เตรียมไว้ แต่ยังไม่มี acceptance บนเครื่องสะอาดที่ไม่มี SDK ผลครบสามตาคือ:

rock beats scissors
paper beats rock
scissors beats paper
Wins: 3

Procedure LosingMove(player As String) As String
  If player = "rock" Then
    Return "scissors"
  ElseIf player = "paper" Then
    Return "rock"
  EndIf
  Return "paper"
EndProcedure

Procedure Main()
  Let moves As Array Of String = ["rock", "paper", "scissors"]
  Let wins As Integer = 0
  For Each player As String In moves
    PrintLn(player + " beats " + LosingMove(player))
    wins += 1
  Next
  PrintLn("Wins: " + wins.ToString())
EndProcedure

กฎกับคะแนนต้องสอดคล้องกัน

LosingMove รับท่าผู้เล่นแล้วคืนท่าที่แพ้มัน หากผู้เล่นเป็น rock คืน scissors; ถ้าเป็น paper คืน rock; ทางที่เหลือคืน paper ซึ่งตั้งใจให้เป็นกรณี scissors ในรายการทดสอบ Main เดิน array ของท่าทั้งสาม พิมพ์คู่ที่เกิดขึ้น และเพิ่ม wins หนึ่งครั้งต่อรอบ ถ้าผลบรรทัดใดกลับความสัมพันธ์ คะแนนสามยังอาจพิมพ์ได้ เพราะโค้ดนับทุกตาโดยสมมติว่ากฎถูก การตรวจ output จึงต้องดูทั้งคู่ท่าและคะแนน ไม่ใช่คะแนนเพียงบรรทัดเดียว

รุ่นนี้ไม่ได้พิสูจน์ว่าชนะทุก input ที่เป็นไปได้: ถ้าเรียก LosingMove("lizard") ฟังก์ชันจะคืน paper ทั้งที่ไม่มีท่า lizard ในเกม ก่อนรับค่าจากผู้ใช้จริงต้องตรวจว่ามีเพียงสามท่าที่อนุญาต และอาจแปลงตัวพิมพ์ก่อนเปรียบเทียบ อีกประเด็นคือการแอบดูท่าก่อนเลือกทำให้เกมไม่ยุติธรรม ถ้านำไอเดียนี้ไปใช้กับคนอื่น ควรบอกว่าเป็นเกมสาธิตกฎ ไม่ใช่คู่แข่งสุ่มอย่างแท้จริง

ลองต่อ

  1. สลับลำดับท่าใน array แล้วตรวจว่าคะแนนและคู่ที่ชนะยังถูก
  2. เพิ่มฟังก์ชัน Wins(player, computer) ที่ตรวจความสัมพันธ์จริง แทนการเพิ่มคะแนนโดยเชื่อ LosingMove
  3. เพิ่มการตรวจ input ที่ไม่ใช่ rock/paper/scissors และนิยามผลลัพธ์ที่อ่านเข้าใจได้
