WBasic 拡張機能ガイド

5 · 診断を読み、クイックフィックスを使う

構文・型・実行基盤のエラーを区別し、キーワードの大文字小文字を安全に修正する

対象バージョン — 対応する private experimental 0.2.0 一式。 このガイドは Windows/macOS ARM64 の compiler/runtime 0.2.0、protocol 0.1.0、VS Code extension 0.3.0 を対象とします。旧 0.1.0/extension 0.2.1 とローカル修正版 0.2.3 は別の履歴です。extension の更新だけで E01–E10 は利用可能になりません。最初に WBasic: Show Toolchain Status でバージョンと capability を確認してください。

役に立つ診断は、「間違い」と言うだけではありません。ファイル、位置、処理段階、コードを示し、セミコロンを適当に足すのではなく、原因を直せるようにします。そもそもセミコロンで WBasic は救えません。

型エラーを作る

一時的に Main を次のように変更します。

Procedure Main()
  Let count As Integer = 3
  If count Then
    PrintLn("ไม่ควรผ่าน")
  EndIf
EndProcedure

If の条件は Boolean でなければならないので、コンパイラは count の範囲を示して診断を報告します。Problems パネルで項目を選ぶと、その位置に戻れます。次のように直します。

If count > 0 Then

未保存の診断と保存済みプロジェクト

言語サーバーは未保存のソースを、上限のあるオーバーレイとしてコンパイラに送るため、一文字ごとに保存しなくても入力中の内容を解析できます。古いテキストに対する遅れて届いた結果は破棄され、新しい診断を置き換えません。

マニフェストと依存の操作は、保存済みプロジェクトを使います。インポートやモジュールのパスに関するエラーでは、ファイルを保存して Check Project を実行してください。

プロジェクトサービスは、開いている未保存ファイルを、上限のあるプロジェクトスナップショットとして一緒に解析します。マニフェストや依存が変わった場合や、スナップショットが拒否された場合は、影響するすべてのオーバーレイの古い結果を消します。ディスク上の全体を確認するには、保存して Check Project を実行します。

キーワード表記のクイックフィックス

キーワードの大文字小文字が不正で WB200 または WB201 が報告されると、拡張機能がその範囲の Quick Fix を提案する場合があります。適用前に、候補のソースをコンパイラで確認します。ファイル中の同じ語を一括置換したり、コメントや文字列を編集したりはしません。

診断位置で Ctrl+. を押し、候補を確認してください。認識できるキーワードに対応する WB200/WB201 の正確な範囲だけを修正します。確認中に別のプロジェクトオーバーレイが変われば古い結果は破棄されます。CRLF ファイルの列 0 の診断でも現在行だけを編集し、前の行には触れません。

修正候補がないことは、拡張機能の故障を意味しません。安全な編集が存在しないか、接続したコンパイラが quickFix 機能を公開していない可能性があります。
