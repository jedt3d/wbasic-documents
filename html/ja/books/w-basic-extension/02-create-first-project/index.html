WBasic 拡張機能ガイド

2 · 最初のプロジェクトを作る

New Project で、マニフェスト、ソース、テストのひな形を手作業なしで作成する

バージョンの範囲 — 非公開 v0.1.0 プレリリース。 この手順は、固定済みソース 3901cf17 の公開済み実験的コンパイラ／ランタイム 0.1.0、同梱の拡張機能 wbasic-dev.wbasic@0.2.1、プロトコルパッケージ 0.0.2 を使います。対応するパッケージのガイド から始めてください。古い非公開コンパイラ 0.0.2 は拡張機能 0.1.0 を同梱し、これらのプロジェクト編集機能を持ちません。

コンパイラと Test Explorer が期待する構成に揃えるため、拡張機能で MyFirstWBasic を作ります。

コマンドパレットから作成する

  1. コマンドパレットを開きます。
  2. WBasic: New Project を選びます。
  3. プロジェクトのルートにする空のフォルダーを選びます。
  4. プロジェクト名を MyFirstWBasic にします。
  5. VS Code に提案されたら、そのフォルダーをワークスペースとして開きます。

プロジェクト名は、コンパイラが受け付ける NFC 正規化された Unicode 識別子である必要があります。タイ語の名前も使えますが、Unicode の正規化だけが異なる名前は避けましょう。人には同じ語に見えても、ツールは筆跡鑑定のように比較しなければなりません。

このコマンドは既存ファイルを上書きしないので、作成先は空でなければなりません。次の構成を作ります。

MyFirstWBasic/
|-- App.wproj
|-- src/
|   `-- Main.wbas
`-- tests/
    |-- main_spec.wbas
    `-- test-catalog.json

生成する App.wproj の toolchain には、選択中のコンパイラが報告するバージョンを書き込みます。このガイドに対応するコンパイラなら 0.1.0 です。先へ進む前に確認してください。別のコンパイラを選んだ場合は、そのコンパイラの報告する値になります。

四つのファイルを知る

App.wproj はマニフェストです。プロジェクト名、モジュール、入口のソース、ツールチェーン、直接依存を宣言します。src/Main.wbas は開始用のプログラムです。

tests/main_spec.wbas にはテストのソースが、tests/test-catalog.json にはネイティブランナーが使うテスト行が入ります。拡張機能はコンパイラからケースの識別情報を読み、テスト名を独自に作ることはありません。

アクティブなプロジェクトを選ぶ

ワークスペースに .wproj が一つなら、拡張機能が自動選択します。複数ある場合は WBasic: Select Active Project を使います。選択はワークスペースのフォルダーごとに保存されるため、複数ルートでも、右のプロジェクトを選んだつもりなのに左を黙ってビルドすることはありません。

WBasic Projects を開き、マニフェストが見えなければ更新します。この画面には、選択したプロジェクトの入口ソース、名前空間、依存、プロファイル、ツールチェーンが表示されます。

練習

App.wproj の [project] の下で新しい行を書き始め、キー補完を見たら変更を元に戻します。補完リストは便利ですが、全部そろえなければならないコレクションではありません。

確認項目

  • 示した構成に四つのファイルがある。
  • App.wproj の言語モードが WBasic Manifest である。
  • Main.wbas の言語モードが WBasic である。
  • WBasic Projects に正しいプロジェクトと入口が表示される。
