Tower of Hanoi has pegs A, B, and C and disks of different sizes. Move one disk at a time, never placing a larger disk on a smaller one. Solving three disks follows the pattern for two: move the upper group to the spare peg, move the largest disk, then move the group to the target. This chapter prints a legal solution generated by recursion. It does not accept player moves.

## Try running it

```powershell
wb check main.wbas --json
wb run main.wbas
```

```text
disk 1: A -> C
disk 2: A -> B
disk 1: C -> B
disk 3: A -> C
disk 1: B -> A
disk 2: B -> C
disk 1: A -> C
moves 7
```

## Divide the problem

{{< project-source "77-tower-of-hanoi-puzzle" >}}

`Move(disks, source, spare, target)` stops when `disks` is zero. Otherwise it moves `disks - 1` to the spare peg recursively, prints the largest disk's move to the target, and recursively moves the upper group onto it. The pegs exchange roles at each call. Trace the two-disk case with a pencil before reading the three-disk trace.

The move count obeys `T(n) = 2T(n-1) + 1`, so it is `2^n - 1`. The program doubles a value in a loop to calculate it and limits the example to 1–8 disks to bound printed output. That limit belongs to this example, not to all WBasic recursion.

## Check it yourself

One disk needs one move from A to C. Two need three, with no large disk placed above a small one. Draw three pegs and update them for each of the seven output moves. As an extension, write an independent peg-state checker to verify each move, separating *solution generation* from *solution checking*.

## Scope and origin

Inspired by [Project 77: Tower of Hanoi Puzzle](https://inventwithpython.com/bigbookpython/project77.html) by Al Sweigart. This WBasic example generates a fixed three-disk solution; it is neither an interactive game nor a peg drawing.
