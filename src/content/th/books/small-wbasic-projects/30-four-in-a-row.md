เกมนี้ให้หมากตกถึงช่องว่างต่ำสุดของคอลัมน์ แล้วตรวจว่าผู้เล่นคนล่าสุดมีหมากติดกันสี่ตัวหรือไม่ ตัวอย่างเป็น **การเล่นซ้ำจากลำดับคอลัมน์ที่กำหนดไว้** ไม่รับคำสั่งสดจากผู้เล่น และจบที่ชัยชนะครั้งแรก เราจึงแยกการตรวจแกนกฎออกจากส่วนรับข้อมูลที่อาจเพิ่มภายหลังได้ชัดเจน

## ลองรัน

ดาวน์โหลดไฟล์ข้างบน เปิด terminal ในโฟลเดอร์นั้น และใช้ `wb` กับ native toolchain ที่ตั้งค่าไว้ตามคู่มือเริ่มต้น:

```powershell
wb check main.wbas --json
wb run main.wbas
```

```text
X wins
.......
.......
X......
XO.....
XO.....
XO.....
```

ลำดับ `[0, 1, 0, 1, 0, 1, 0]` ใช้เลขคอลัมน์แบบเริ่มที่ศูนย์ X ลงคอลัมน์ซ้ายสุดสี่ครั้ง ส่วน O ลงคอลัมน์ถัดไปสามครั้ง บรรทัดแรกของกระดานจึงยังว่างทั้งหมด

## อ่านโค้ดเป็นขั้น

{{< project-source "30-four-in-a-row" >}}

กระดานเป็น Array หนึ่งมิติขนาด 42 ช่อง ตำแหน่ง `row * 7 + col` ทำให้เดินตามแถวได้ โดย `row = 0` คือแถวบนสุด ก่อนวางหมาก โปรแกรมเริ่มค้นจากแถว 5 ขึ้นไปจนพบจุด `.` ถ้าค้นเลยแถวบน แปลว่าคอลัมน์เต็ม การตรวจเลขคอลัมน์และคอลัมน์เต็มเกิดก่อนเขียน Array เสมอ

`Four` รับช่องที่เพิ่งลงและตรวจสี่ทิศหลัก: แนวนอน แนวตั้ง และแนวทแยงสองแบบ ในแต่ละทิศมันนับหมากสีเดียวกันทั้งด้านบวกและด้านลบ จึงจับแนวที่หมากล่าสุดตก **ตรงกลาง** ของสี่ตัวได้ด้วย หากตรวจเพียงด้านเดียว กรณีนั้นจะหลุดไป เมื่อรวมได้อย่างน้อยสี่ โปรแกรมรายงานผู้ชนะทันที ไม่สลับฝ่ายก่อน

## ทดลองเปลี่ยนกฎ

ลอง `[0, 0, 0, 0, 0, 0, 0]`: หลังหกตา คอลัมน์เต็มและตาที่เจ็ดต้องรายงาน `full column` โดยไม่เข้าถึง index ติดลบ เปลี่ยนตัวแรกเป็น `7` ควรรายงาน `invalid column` อีกกรณีคือจัดลำดับให้ชนะในแนวนอนหรือทแยง แล้วตรวจว่าการนับสองด้านยังทำงาน

คำถามต่อยอด: จะตรวจเสมอเมื่อครบ 42 ช่องอย่างไร โดยไม่ประกาศเสมอในตาที่เกิดชัยชนะ? หากเพิ่ม `ReadLine()` ให้เก็บฟังก์ชันตรวจชัยชนะเดิมไว้และทดสอบอินพุตผิดรูปแยกต่างหาก
