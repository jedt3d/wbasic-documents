## เป้าหมายและขอบเขต

คำถามหลอกให้เราตรวจสมมติฐานของตัวเอง บทนี้มีสองข้อที่แต่งใหม่: การเอาป้ายออกจากกล่องไม่ได้เอาปากกาออก และการทดสอบที่รีเซ็ต fixture ทุกครั้งไม่แชร์สถานะระหว่างรอบ โปรแกรมเก็บคำถาม เฉลย และคำตอบจำลองไว้สาม array แล้วตรวจทีละข้อ คำตอบแรกตั้งใจผิด ส่วนคำตอบที่สองถูก เพื่อให้เห็นทั้งทางเฉลยและทางเพิ่มคะแนน เราใช้คำตอบจำลองแทน input สด เพื่อให้ผลตรวจบทเรียนคงที่

## เตรียมและรัน

ดาวน์โหลด `main.wbas` เปิดเทอร์มินัลในโฟลเดอร์ของไฟล์ แล้วใช้ `wb` บนเครื่องพัฒนาที่มี native SDK/runtime คู่กัน:

```console
wb check main.wbas --json
wb run main.wbas
```

`run` คอมไพล์ ลิงก์ และรัน หากสร้างชุดเครื่องมือเองให้ใช้ `cargo build --workspace --locked` ที่รากคลังผลิตภัณฑ์ก่อน `wb build` ยังไม่เปิดเป็นคำสั่งผู้ใช้ ผลครบสองข้อคือ:

```text
Q1: A box holds five pens. Remove its label: how many pens remain?
scripted guess: 3
Answer: 5
Q2: Two tests reset their fixtures. How many runs share state?
scripted guess: 0
Correct
Score: 1/2
```

## ข้อมูลสามชุดต้องเดินพร้อมกัน

`index` เริ่มที่ศูนย์และจบก่อนความยาว `questions` แต่ละตำแหน่งเชื่อมคำถาม เฉลย และคำตอบจำลองของข้อเดียวกัน `index + 1` ใช้แสดงเลขข้อแบบที่คนคุ้นเคย โดยไม่เปลี่ยนดัชนีที่ใช้กับ array เมื่อคำตอบตรงกันหลังแปลงเป็นตัวเล็ก โปรแกรมเพิ่ม `score` และพิมพ์ `Correct`; ถ้าไม่ตรงจึงเผยเฉลย สุดท้ายพิมพ์คะแนนเทียบกับจำนวนคำถามจริง ไม่ใส่ตัวเลข 2 ตายตัวในบรรทัดสรุป

แบบข้อมูลนี้มีข้อจำกัดสำคัญ: ถ้าเพิ่มคำถามแต่ลืมเพิ่มเฉลยหรือคำตอบจำลอง array จะยาวไม่เท่ากันและการเข้าถึงตำแหน่งอาจล้มเหลว รุ่นที่โตขึ้นควรเก็บข้อมูลแต่ละข้อรวมกันใน `Structure` เดียว และตรวจจำนวนข้อก่อนเริ่มเล่น การเทียบข้อความตรงตัวก็ยอมรับเพียงรูปคำตอบที่กำหนด เช่น `five` จะไม่เท่ากับ `5` แม้คนเข้าใจเหมือนกัน อย่าเพิ่มการจับคำแบบกว้างโดยไม่คิดถึงคำตอบผิดที่มีคำเฉลยปะปน

## ลองต่อ

1. สลับคำตอบจำลองข้อแรกเป็น `5` แล้วคำนวณคะแนนใหม่ก่อนรัน
2. เพิ่มข้อที่สามพร้อมคำตอบและคำตอบจำลองให้ครบทั้งสาม array แล้วตรวจเลขข้อกับตัวหารคะแนน
3. ออกแบบ `Structure Question` ที่มีคำถามและเฉลยอยู่ด้วยกัน เพื่อลดความเสี่ยงของ array ยาวไม่เท่ากัน
