บทนี้สร้าง **แกนเกมแบบ replay** ด้วยลำดับเดินที่กำหนดไว้ ยังไม่ใช่เกมรับผู้เล่นสองคนผ่าน keyboard เราเริ่มตรงกฎที่ทดสอบได้แน่นอนก่อน ได้แก่ ช่องที่ว่าง การสลับฝ่าย และเส้นชนะ ทั้งหมดเขียนด้วย Array และ procedure ได้ ไม่ต้องมี game library

## รันลำดับตัวอย่าง

เตรียม `wb` กับ native toolchain ตาม Getting Started แล้วใช้คำสั่งในโฟลเดอร์ที่ดาวน์โหลด:

```powershell
wb check main.wbas --json
wb run main.wbas
```

```text
X wins
XXX
OO.
...
```

ตำแหน่งภายในเริ่มที่ 0 เรียงซ้ายไปขวาทีละแถว ลำดับ `[0, 3, 1, 4, 2]` จึงให้ X ครองแถวแรกก่อน O ได้เดินครั้งที่สาม

## กระดานกับเส้นชนะ

{{< project-source "76-tic-tac-toe" >}}

`board` มีเก้าช่องและใช้จุดแทนช่องว่าง ส่วน `lines` บันทึกชุด index ที่ทำให้ชนะทั้งแปดเส้น ได้แก่สามแถว สามคอลัมน์ และสองแนวทแยง การเก็บกฎที่ซ้ำเป็นข้อมูลช่วยให้ `Won` มีเพียงลูปเดียว ไม่ต้องเขียน `If` แปดชุดที่ต่างกันเพียงเลขตำแหน่ง

`Won` อ่านกระดานโดยไม่เปลี่ยนมัน และต้องตรวจว่าทั้งสามช่องเป็น `mark` เดียวกับผู้เล่นที่ถาม การตรวจแค่ว่าสามช่องเท่ากันจะทำให้จุดสามจุดถูกนับเป็นผู้ชนะ ซึ่งเป็นชัยชนะที่ยังไม่มีใครลงแข่ง

ก่อนเขียนกระดาน `Main` ตรวจช่วง index และตรวจช่องว่าง หากข้อมูลผิดจะพิมพ์เหตุผลแล้วจบ replay เมื่อเดินสำเร็จให้ตรวจชนะทันที ก่อนสลับฝ่าย วิธีนี้ทำให้ข้อความผู้ชนะยังหมายถึงคนที่เพิ่งเดิน

## ลองทำให้ผิดอย่างตั้งใจ

เปลี่ยนลำดับเป็น `[0, 0]` ต้องได้ `occupied position`; เปลี่ยนเป็น `[-1]` หรือ `[9]` ต้องได้ `invalid position` แทน bounds error การป้องกัน input จึงเกิดก่อนการเข้าถึง Array

ลอง `[0, 1, 4, 2, 8]` เพื่อชนะทแยง และ `[0, 1, 3, 2, 6]` เพื่อชนะคอลัมน์ ในกรณีเดินยังไม่ชนะ โปรแกรมจะแสดงกระดานโดยไม่มีข้อความผู้ชนะ

## ต่อเป็นเกมโต้ตอบ

สิ่งที่ยังไม่ทำคือรับตำแหน่งจาก `ReadLine()`, ตรวจตัวเลขและให้ลองใหม่, ประกาศเสมอเมื่อเก้าช่องเต็ม และถามเล่นอีกครั้ง สิ่งเหล่านี้เป็นงานบทเรียนต่อยอดที่ใช้ Core I/O กับ control flow ได้ ไม่ใช่ API ที่ WBasic ขาด และไม่มี AI ในตัวอย่างนี้

ก่อนเพิ่มหน้าจอ ให้แยกขั้นตอนรับคำสั่งออกจากกฎเดิน เพื่อเก็บ replay เดิมเป็น regression fixture ได้ หากเลือกใช้ TUI ภายหลัง ต้องตรวจ event และ terminal lifecycle ต่างหาก ไม่ถือว่า replay ผ่านแล้วแปลว่า TUI ผ่านด้วย
