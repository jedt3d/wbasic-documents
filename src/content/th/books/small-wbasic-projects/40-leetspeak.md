## เป้าหมายและขอบเขต

ลีตสปีคเป็นการเล่นกับหน้าตาของอักษร เช่นแทน `A` ด้วย `4` และ `E` ด้วย `3` บทนี้สร้างตัวแปลงข้อความสั้น `WBasic is neat!` โดยกำหนดคู่แทนที่หกตัว ได้แก่ A, E, I, O, S และ T ผลจึงเหมือนเดิมทุกครั้ง ต่างจากบางรุ่นที่สุ่มเลือกระหว่างตัวแทนหลายแบบ การจำกัดแผนที่ช่วยให้ผู้อ่านตรวจหนึ่งอักษรต่อหนึ่งอักษร และมองเห็นชัดว่าตัวที่ไม่อยู่ในแผนที่ถูกเก็บไว้

## เตรียมและรัน

ดาวน์โหลด `main.wbas` แล้วเปิดเทอร์มินัลในโฟลเดอร์ที่เก็บไฟล์ เครื่องพัฒนาต้องมี `wb` กับ native SDK/runtime ที่เข้าคู่กัน:

```console
wb check main.wbas --json
wb run main.wbas
```

คำสั่ง `run` คอมไพล์และลิงก์ก่อนรัน ถ้าสร้าง `wb` เองให้ใช้ `cargo build --workspace --locked` ที่รากคลัง WBasic ก่อน หลักฐานตัวอย่างนี้ใช้ compiler `2614b37` ส่วน compiler 0.0.2 ที่รวมใน main แล้วมี `wb build` สำหรับ project `.wproj` พร้อม debug/release; ไม่รับ standalone `.wbas` แพ็กทดลองมีเครื่องมือ link เตรียมไว้ แต่ยังไม่มี acceptance บนเครื่องสะอาดที่ไม่มี SDK ผลลัพธ์ที่ตรวจได้คือ:

```text
WBasic is neat!
WB451c 15 n347!
```

## อ่านการแทนที่ทีละอักษร

`Leet` เดินข้อความด้วย `For Each` และแปลงอักษรปัจจุบันเป็นตัวเล็กเพื่อใช้ตัดสินใจ `a` หรือ `A` จึงเข้ากฎเดียวกัน ถ้าตรงกับกฎใดก็เติมตัวเลขลงผลลัพธ์ ถ้าไม่ตรงก็เติมตัวเดิม คำว่า `WBasic` จึงเหลือ `W` กับ `B` ตามเดิม แต่ `a`, `s`, `i` เปลี่ยนเป็น `4`, `5`, `1` ตามลำดับ การสะสมด้วย `result += ...` สำคัญมาก ถ้าใช้ `result = ...` ทุกครั้ง โปรแกรมจะเหลือเพียงตัวแทนของอักษรสุดท้าย

การแปลงนี้ไม่ใช่การเข้ารหัสลับ และโดยทั่วไปย้อนกลับไม่ได้อย่างแน่นอน: ตัวเลข `4` ในข้อความเดิมกับ `A` ที่ถูกแทนเป็น `4` ดูเหมือนกันหลังแปลง รุ่นนี้รักษาช่องว่าง เครื่องหมายตกใจ อักษรไทย และอักษรที่ไม่ได้ระบุไว้โดยไม่เปลี่ยน การเรียก `.ToLower()` ใช้เพื่อเลือกกฎเท่านั้น ไม่ได้บังคับให้ผลทั้งหมดเป็นตัวเล็ก จึงคงรูปตัวอักษรที่ไม่ถูกแทนไว้ได้

## ลองต่อ

1. เพิ่มกฎ `B` เป็น `8` แล้วทำนายบรรทัดที่สองใหม่ก่อนรัน
2. ลองข้อความที่มีตัวเลข `4` จริง แล้วอธิบายเหตุใดการถอดกลับจึงกำกวม
3. ย้ายกฎไปไว้ใน array คู่ของต้นฉบับและตัวแทน เพื่อขยายตารางโดยไม่เพิ่ม `ElseIf` หลายสิบแขนง
