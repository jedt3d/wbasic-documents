## เป้าหมายและขอบเขต

ลองนึกถึงรูปเล็ก ๆ ที่มีเพียงช่องว่างกับช่องที่ต้องระบายสี เราเก็บรูปนั้นเป็นข้อความห้าแถว โดยใช้ `#` บอกตำแหน่งที่ต้องแสดงตัวอักษร และเว้นวรรคบอกพื้นหลัง โปรแกรมนำข้อความ `HI` มาหมุนใช้ซ้ำในตำแหน่งทึบ รูปที่ได้จึงประกอบจากข้อความจริง ไม่ใช่ภาพที่พิมพ์เตรียมไว้ บทนี้ใช้บิตแมปขนาดเล็กเพื่อให้เห็นการเลือกแต่ละช่องอย่างชัดเจน และไม่รับข้อความจากแป้นพิมพ์ ผลจึงแน่นอนทุกครั้ง

## เตรียม รัน และสังเกตผล

ดาวน์โหลด `main.wbas` เปิดเทอร์มินัลในโฟลเดอร์ที่เก็บไฟล์ แล้วใช้ `wb` บนเครื่องพัฒนาที่มี native SDK และ runtime คู่กัน:

```console
wb check main.wbas --json
wb run main.wbas
```

`run` คอมไพล์และลิงก์ก่อนรัน หากสร้างชุดเครื่องมือจากคลัง WBasic ให้ใช้ `cargo build --workspace --locked` ที่รากคลังผลิตภัณฑ์ก่อน หลักฐานตัวอย่างนี้ใช้ compiler `2614b37` ส่วน compiler 0.0.2 ที่รวมใน main แล้วมี `wb build` สำหรับ project `.wproj` พร้อม debug/release; ไม่รับ standalone `.wbas` แพ็กทดลองมีเครื่องมือ link เตรียมไว้ แต่ยังไม่มี acceptance บนเครื่องสะอาดที่ไม่มี SDK ผลมีช่องว่างทั้งหน้าและท้ายแถวบางแถว อย่าลบทิ้งเมื่อตรวจรูป:

```text
Bitmap message: HI
  H  
 IHI 
HIHIH
 IHI 
  H  
```

## ทำไมตัวอักษรจึงวนกลับมา

`mask` เป็น array ของ String หนึ่งสมาชิกต่อหนึ่งแถว วงนอกเลือกแถว วงในเดินจากคอลัมน์ศูนย์ไปถึงคอลัมน์สุดท้าย ถ้าช่องในแผนที่เป็นช่องว่างก็เติมช่องว่างลง `line` ตรง ๆ มิฉะนั้นเลือกตัวอักษรจาก `message` ด้วย `column Mod message.Length` เมื่อ `message` ยาวสองตัว คอลัมน์ 0, 2, 4 จึงใช้ `H`; คอลัมน์ 1, 3 ใช้ `I` การใช้หมายเลขคอลัมน์ทำให้ลวดลายในแต่ละแถวอยู่ในจังหวะเดียวกัน

เราสร้าง `line` ใหม่ทุกแถว แล้ว `PrintLn` เพียงครั้งเดียวหลังจบวงใน หากย้ายการสร้าง `line` ออกไปก่อนวงนอก แถวถัดไปจะต่อท้ายแถวเก่า และรูปจะพังเงียบ ๆ `#` เป็นเพียงเครื่องหมายบอกช่องทึบ จะเปลี่ยนเป็น `X` ก็ยังได้รูปเดิม เพราะเงื่อนไขสนใจแค่ว่าเป็นช่องว่างหรือไม่ จุดที่ต้องระวังคือข้อความว่าง: `column Mod message.Length` จะกลายเป็นการหารด้วยศูนย์ รุ่นที่รับข้อความจากผู้ใช้ต้องตรวจความยาวก่อนเริ่มวาด
