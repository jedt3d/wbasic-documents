## เป้าหมายและขอบเขต

ข้อความสลับตัวพิมพ์ใหญ่น้อยดูราวกับคนพิมพ์โดยกด Shift เป็นจังหวะ บทนี้เปลี่ยน `WBasic is fun!` ให้ตัวอักษรอังกฤษตัวแรกเป็นตัวเล็ก ตัวถัดไปเป็นตัวใหญ่ แล้วสลับต่อไป โดยไม่นับช่องว่างหรือเครื่องหมายตกใจเป็นจังหวะ โปรแกรมตั้งใจ **ไม่สุ่ม** จึงใช้เป็นโจทย์เรื่องสถานะ Boolean ที่ตรวจด้วยตาได้ อีกทั้งเห็นชัดว่าความยาวข้อความกับจำนวนอักษรที่ถูกแปลงไม่ใช่สิ่งเดียวกัน

## เตรียมและรัน

ดาวน์โหลด `main.wbas` แล้วเปิดเทอร์มินัลในโฟลเดอร์นั้น เครื่องพัฒนาต้องมี `wb` และ native SDK/runtime คู่กัน:

```console
wb check main.wbas --json
wb run main.wbas
```

`run` คอมไพล์ ลิงก์ แล้วรัน หากสร้าง `wb` จาก checkout ของ WBasic เอง ให้ใช้ `cargo build --workspace --locked` ที่รากคลังก่อน หลักฐานตัวอย่างนี้ใช้ compiler `2614b37` ส่วน compiler 0.0.2 ที่รวมใน main แล้วมี `wb build` สำหรับ project `.wproj` พร้อม debug/release; ไม่รับ standalone `.wbas` แพ็กทดลองมีเครื่องมือ link เตรียมไว้ แต่ยังไม่มี acceptance บนเครื่องสะอาดที่ไม่มี SDK ผลที่ควรได้คือ:

```text
WBasic is fun!
wBaSiC iS fUn!
```

## สถานะหนึ่งบิตกำหนดอักษรถัดไป

`upperNext` เริ่มเป็น `False` หมายถึงอักษรอังกฤษตัวแรกควรเป็นตัวเล็ก วง `For Each` เดินข้อความทีละตัว และใช้ `letters.Contains(character)` ตรวจว่าเป็นอักษร ASCII a–z หรือ A–Z หรือไม่ ถ้าใช่จึงแปลงด้วย `.ToUpper()` หรือ `.ToLower()` ตามสถานะ แล้วสลับสถานะด้วย `Not upperNext` ถ้าไม่ใช่ เช่นช่องว่างหรือ `!` ก็เติมตัวเดิมและไม่แตะสถานะ ดังนั้นหลัง `WBasic` ซึ่งมีหกตัว จังหวะของ `is` ยังคงเริ่มที่ตัวเล็ก

เหตุผลที่ไม่ใช้ดัชนีอักขระ `index Mod 2` โดยตรงคือช่องว่างจะนับเข้าไปด้วย ทำให้ตัวแรกหลังช่องว่างมีจังหวะกลับกันโดยไม่ตั้งใจ เงื่อนไขนี้เป็นการออกแบบ ไม่ใช่กฎสากลของ spongecase บางรุ่นเลือกสุ่มให้สลับไม่สม่ำเสมอ รุ่นของเราไม่ทำเช่นนั้นเพื่อให้การตรวจผลทำซ้ำได้ และยังไม่พยายามนิยามการสลับตัวพิมพ์ของภาษาไทย ซึ่งไม่มีคู่ใหญ่เล็กแบบ A–Z

## ลองต่อ

1. ใส่ตัวเลข `123` ระหว่างสองคำ แล้วตรวจว่าจังหวะของอักษรหลังตัวเลขยังต่อเนื่อง
2. เปลี่ยนให้เริ่มด้วยตัวใหญ่ โดยแก้สถานะเริ่มต้นเพียงแห่งเดียว
3. เปลี่ยนกฎให้ช่องว่างรีเซ็ตสถานะ เพื่อให้แต่ละคำเริ่มตัวเล็กเสมอ แล้วเปรียบเทียบผล
