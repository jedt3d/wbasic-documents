## 目的と範囲

リート表記は、`A`を`4`、`E`を`3`に替えるように、文字の見た目を変えて遊びます。この章では固定の文`WBasic is neat!`を、A、E、I、O、S、Tの6つの規則で変換します。複数の候補からランダムに選ぶ版と違い、結果は毎回同じです。小さな表なら各文字を確認し、規則にない文字がそのまま残ることも分かります。

## 準備と実行

`main.wbas`をダウンロードし、そのフォルダーで端末を開きます。開発用マシンには`wb`と対応するネイティブSDKおよびランタイムが必要です。

```console
wb check main.wbas --json
wb run main.wbas
```

`run`は実行前にコンパイルとリンクを行います。`wb`を自分でビルドする場合は、まずWBasicリポジトリのルートで`cargo build --workspace --locked`を実行します。記録済みの例ではコンパイラ`2614b37`を使用しています。統合済みのコンパイラ0.0.2の`wb build`はデバッグ／リリース構成の`.wproj`プロジェクト向けであり、単独の`.wbas`ファイル向けではありません。実験用パッケージにはリンク用ツールが含まれます。SDKのない新しいマシンでの受け入れは未完了です。次の出力を確認してください。

```text
WBasic is neat!
WB451c 15 n347!
```

## 文字ごとに置換を読む

`Leet`は`For Each`で文字列をたどり、規則を選ぶため現在の文字を小文字にします。したがって`a`と`A`は同じ規則です。一致すれば数字を追加し、そうでなければ元の文字を追加します。`WBasic`では`W`と`B`は残り、`a`、`s`、`i`は`4`、`5`、`1`になります。`result += ...`で蓄積することが重要です。毎回`result = ...`にすると最後の文字の置換しか残りません。

これは暗号ではなく、一般に曖昧さなく元へ戻せません。元からある`4`と`A`から置き換えた`4`は、後では同じに見えます。この版は空白、句読点、タイ文字、規則にないすべての文字を保ちます。`.ToLower()`は規則を選ぶだけで、結果全体を小文字にするわけではありません。

## 次に試すこと

1. `B`→`8`を追加し、実行前に新しい2行目を予測しましょう。
2. 元からある数字`4`を含め、復号が曖昧になる理由を説明しましょう。
3. 元の文字と置換後の文字の組を配列に保存し、多くの`ElseIf`分岐なしで表を増やせるようにしましょう。
