駒は列の一番下の空いたセルまで落ちます。各手の後、そのプレイヤーの駒が4つ連続したか調べます。これは**あらかじめ決めた列の再生**で、プレイヤーの直接入力はありません。最初の勝利で停止します。再生により、後から追加できる入力インターフェースとゲーム規則を分けて扱えます。

## 実行してみる

ファイルをダウンロードし、そのフォルダーで端末を開き、「はじめに」で設定したネイティブツールチェーンとともに`wb`を使います。

```powershell
wb check main.wbas --json
wb run main.wbas
```

```text
X wins
.......
.......
X......
XO.....
XO.....
XO.....
```

列の並び`[0, 1, 0, 1, 0, 1, 0]`は0始まりです。Xは一番左の列に4回、Oはその右隣に3回落とします。盤面の最上段は空いたままです。

## 段階ごとにコードを読む

{{< project-source "30-four-in-a-row" >}}

盤面は42セルの一次元配列です。`row * 7 + col`でセルを指定し、`row = 0`が最上段です。駒を置くとき、プログラムは行5から上に向かって`.`を探します。最上段を超えたら列は満杯です。配列に書き込む前に列番号と空きの有無を確認します。

`Four`は直近のセルについて、水平、垂直、2つの対角線という4方向を調べます。各方向で正と負の両側に続く同じ駒を数えるため、列の**中央**に置いた新しい駒で四目が完成する場合も見つけられます。片側だけでは見落とします。4つ見つかると、手番を変える前に勝者を報告します。

## 規則を変えて試す

`[0, 0, 0, 0, 0, 0, 0]`を試しましょう。6手で列が埋まり、7手目は負の添字にアクセスせず`full column`と報告するはずです。最初の列を`7`にすると`invalid column`になります。水平または対角線の勝利を作り、両側の数え方を確認しましょう。

42セルを使い切ったとき、勝利した手を引き分けと誤報せずにどう検出しますか。`ReadLine()`を追加するなら、既存の勝利判定を残し、不正な入力を別に試してください。
