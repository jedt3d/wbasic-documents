この章では、あらかじめ決めた手を使って**ゲームの中心的な規則を再生**します。2人がキーボードで対戦するゲームではありません。空きマス、交互の手番、勝利する列は、ゲーム用ライブラリがなくても配列と手続きで試せます。

## 手順を再生する

『はじめに』に従って`wb`とネイティブツールチェーンを準備し、ダウンロードしたファイルのフォルダーで次を実行します。

```powershell
wb check main.wbas --json
wb run main.wbas
```

```text
X wins
XXX
OO.
...
```

内部の位置は0から始まり、各行を左から右へ読みます。`[0, 3, 1, 4, 2]`の順なら、Oの3手目より前にXが最上段を完成させます。

## 盤面と勝利の列

{{< project-source "76-tic-tac-toe" >}}

`board`には9つのマスがあり、空きは点で表します。`lines`には勝利する8つの3マスの組、つまり横3列、縦3列、斜め2列を記録します。繰り返す規則をデータにすれば、`Won`はほとんど同じ`If`を8つ並べずに1つのループで済みます。

`Won`は盤面を変えずに読み、3マスすべてが指定されたプレイヤーの`mark`であることを確かめます。3つが等しいだけを調べると、空の点3つまで勝ちになります。`Main`は盤面に書き込む前に、位置の範囲と空き状態を調べます。不正な手は理由を表示して再生を終えます。正しい手はプレイヤーを替える*前*に勝敗を判定するため、勝者は直前に打った人です。

## 意図的に壊してみる

`[0, 0]`なら`occupied position`、`[-1]`または`[9]`なら配列の境界エラーではなく`invalid position`になるはずです。斜めの勝利には`[0, 1, 4, 2, 8]`、縦の勝利には`[0, 1, 3, 2, 6]`を試します。勝者がいなければ、勝利の表示なしに盤面が出ます。

## 対話式へ広げる

`ReadLine()`による位置入力、数の検証と再入力、9マスが埋まったときの引き分け、再戦の問いかけは今後の拡張です。これらはCore I/Oと制御構文で扱えます。この例にAIはありません。入力処理と手の規則を分け、再生を回帰テストに残してください。後でTUIを加えるなら、イベントと端末の開始・終了を別に検証します。この再生の合格はTUIの検証にはなりません。
