## 目的と範囲

空白と塗りつぶしたセルだけでできた小さな絵を考えましょう。これを5行の文字列で保存します。`#`は文字を表示するセル、空白は背景です。プログラムは塗りつぶすセルで`HI`の文字を繰り返し使います。結果は事前に印刷した絵ではなく、本物のメッセージからできた絵です。小さな固定のビットマップなので、各選択を確認しやすくなっています。キーボード入力はなく、実行するたびに同じ結果になります。

## 準備、実行、観察

`main.wbas`をダウンロードし、そのフォルダーで端末を開きます。対応するネイティブSDKとランタイムがある開発用マシンで`wb`を使います。

```console
wb check main.wbas --json
wb run main.wbas
```

`run`は実行前にコンパイルとリンクを行います。製品リポジトリからWBasicツールをビルドした場合は、まずルートで`cargo build --workspace --locked`を実行します。記録済みの例ではコンパイラ`2614b37`を使用しています。統合済みのコンパイラ0.0.2では、デバッグ／リリース構成の`.wproj`プロジェクト向けに`wb build`を提供しますが、単独の`.wbas`ファイル向けではありません。実験用パッケージにはリンク用ツールが含まれます。SDKのない新しいマシンでの受け入れは未完了です。行によっては先頭と末尾に空白があります。形を確認するときはその空白を残してください。

```text
Bitmap message: HI
  H  
 IHI 
HIHIH
 IHI 
  H  
```

## 文字が繰り返される理由

`mask`は行ごとに1つの文字列を持つ配列です。外側のループで行を選び、内側のループで列0から末尾まで調べます。地図上の空白セルは`line`に空白を追加します。それ以外では`column Mod message.Length`で`message`から文字を選びます。2文字のメッセージなら、列0、2、4は`H`、列1、3は`I`です。列番号を使うことで、行をまたいでも文字の模様がそろいます。

各行で新しい`line`を作り、内側のループが終わってから`PrintLn`を1回呼びます。初期化を外側のループより前に移すと、新しい行が前の行の末尾につながってしまいます。`#`は塗りつぶすセルの印にすぎません。条件分岐は空白とそれ以外を区別するので、`X`に置き換えても形は同じです。メッセージが空だと`column Mod message.Length`は0で割ることになります。利用者入力を受け取る版では、描画前に長さを確認する必要があります。

## 次に試すこと

1. メッセージを`ABC`に変え、実行前に5列の行を手で求めてみましょう。
2. 中央に穴のある長方形の地図を作り、すべての行を同じ長さに保ちましょう。
3. 文字を次の行まで続けてみましょう。列番号とは別に、塗りつぶしたセルをどう数えますか。
