3つの桶には8、5、3リットル入ります。目標はどれか1つの桶に4リットルを入れることです。桶を満たす、空にする、または注ぎ元が空になるか注ぎ先が満杯になるまで別の桶へ注ぐ操作ができます。この例は用意した操作の列を再生し、目標に達したところで止まります。プレイヤーの入力を解析せずに状態遷移を学べます。

## 実行してみる

```powershell
wb check main.wbas --json
wb run main.wbas
```

```text
8L=0 5L=0 3L=0
8L=0 5L=5 3L=0
8L=0 5L=2 3L=3
8L=0 5L=2 3L=0
8L=0 5L=0 3L=2
8L=0 5L=5 3L=2
8L=0 5L=4 3L=3
goal: 4L
```

## 1つの操作を状態変化として読む

{{< project-source "81-water-bucket-puzzle" >}}

`capacity`には固定した容量、`water`には変化する水量を入れます。`actions`は操作の種類・注ぎ元・注ぎ先という3つの数によるコマンドの配列です。種類0は満たす、1は空にする、2は注ぐ操作です。注ぐときは、注ぎ元の水量と注ぎ先の空き容量の小さい方を`amount`とし、同じ量を片方から引き、もう片方へ足します。注ぐ操作では水の総量が保存されます。

配列に触れる前に、プログラムは両方の添字を検証し、同じ桶へ注ぐ操作を禁じます。各操作の後で状態を表示し、*それから*目標を調べるため、達成した状態が見えます。5リットルの桶から、すでに2リットル入っていて残り1リットルだけ受け入れられる3リットルの桶へ注ぐと、5リットルの桶に4リットルが残ります。

## 境界の確認

満杯の桶を満たしても容量を超えてはいけません。空の桶から注げば`amount = 0`で変化しません。最初の操作で注ぎ元の添字を3または-1にした場合、配列を読む前に`invalid bucket`を示すはずです。さらに進めるなら、すでに見た状態を記録しながら最短の解を探索します。各状態は桶ごとの水量で識別できます。
