## プロジェクトの目標

フィボナッチ数列は`F(0) = 0`と`F(1) = 1`から始まり、以後`F(n + 2) = F(n) + F(n + 1)`に従います。配列に数列全体を保存せず、前の2つの値だけを保ち、**F(0)からF(9)までの最初の10項**を印刷します。添字を明示することで、「最初の項」が0か1かという曖昧さを避けます。

## 準備と実行

`main.wbas`をダウンロードし、そのフォルダーで端末を開きます。`wb`と対応するネイティブSDKおよびランタイムを使います。

```console
wb check main.wbas --json
wb run main.wbas
```

`check`はソースを検査し、`run`はコンパイル、リンク、実行を行います。製品のチェックアウトから`wb`をビルドする場合は、まずルートで`cargo build --workspace --locked`を実行します。記録済みの例ではコンパイラ`2614b37`を使用しています。統合済みのコンパイラ0.0.2の`wb build`はデバッグ／リリース構成の`.wproj`プロジェクト向けであり、単独の`.wbas`ファイル向けではありません。実験用パッケージにはリンク用ツールが含まれます。SDKのない新しいマシンでの受け入れは未完了です。

各段階を確認できるよう、添字と値を一緒に表示します。

## 更新の3段階をすべて追う

最初の`previous = 0`と`current = 1`は`F(0)`と`F(1)`を表します。`previous`を印刷し、`following = previous + current`を計算してから、`previous = current`、`current = following`と代入します。最初の反復後は組が`(1, 1)`となり、次の`F(1)`を印刷する準備ができます。`following`を保存せずに再代入すると、すでに変わった値を誤って足してしまいます。

`For`は0から9までで、出力はちょうど10項です。プログラムは`F(9)`を印刷した後にも`following`を計算しますが、その値は表示しません。項数を増やすなら不要な計算を避け、`Integer`の範囲を確認します。フィボナッチ数は急速に増え、いずれオーバーフローします。この小さな例は巨大な項数を受け付けず、無限の数列を計算できるとも主張しません。

## 次に試すこと

1. `For`の上限を1に下げ、`F(0)`と`F(1)`だけが表示されることを確かめましょう。
2. 2と1から始め、4項を予測しましょう。漸化式は同じでも、結果は標準のフィボナッチ数列ではありません。
3. 偶数番目の項だけを印刷しながら、次の値に必要な奇数番目の項も計算しましょう。
