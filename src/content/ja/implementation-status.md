**2026 年 10 月 6 日**に更新しました。[実験的な非公開 v0.1.0 リリース](https://github.com/jedt3d/wbasic-language/releases/tag/v0.1.0) は、Windows／macOS ARM64 向けコンパイラ／ランタイム **0.1.0** と拡張機能 **0.2.1** を公開しています。拡張機能 **0.2.3** は、対応する開発用コンパイラのソース `dfdcbdc` と組み合わせて Windows ARM64 でローカル検証しました。0.2.3 に公開リリースや Marketplace 掲載はありません。CLI、ポータブル ZIP、VS Code で選択するコンパイラは同じバージョンです。以前のダウンロードと公開済み ZIP は変更しません。

コンパイラのリリース番号、言語設計の **draft v0.3**、サイトの公開バージョンは別です。[コンパイラのリリースマニフェスト](https://jedt3d.github.io/wbasic-documents/compiler-release.json) には固定済みのソースと両 ZIP のハッシュが記録されています。コンパイラは心を読めませんが、`wb --version` で解決する謎は意外に多いものです。

## 現在のツールチェーン

| 構成要素 | 現在の範囲 |
|---|---|
| コンパイラ／ランタイム | ネイティブ Windows ARM64 / macOS ARM64 の対応する 0.1.0 の組み合わせ |
| CLI | `check`、`run`、`build`、`emit-object`、`test`、`project-info`、`symbols`、`references`、`tui doctor`、`editor-project`、`editor-manifest` |
| ビルド | プロジェクトマニフェスト、debug/release。本番利用の権限は引き続き false |
| WORM | 実験的 SQLite：型付きマッピング、変更、クエリ、トランザクション、楽観的バージョン検査 |
| VS Code 拡張機能 | Windows ARM64 でローカル検証済みの `wbasic-dev.wbasic@0.2.3`。公開済み ZIP には引き続き `editors/vscode/wbasic-0.2.1.vsix` を同梱 |
| LSP/MCP | プロトコルパッケージ 0.0.2。コンパイラ管理のプロジェクトスナップショットと編集メタデータ |
| プロジェクト／モジュールの固定 | `toolchain = "0.1.0"`。New Project は選択中のコンパイラを自動的に固定 |
| ガイド | 入門、リファレンス、拡張機能ガイドは、このリリースの組み合わせに対応 |

拡張機能とプロトコルパッケージの版は独立しています。拡張機能 0.2.3 では、五つの Check／Run／Build コマンドがコマンドパレットに表示され、実行時には信頼設定と現在のコンパイラ機能を確認します。Run／Build は専用のプロセスタスクを使い、完了後も出力を残します。実際の Windows ウィンドウで発生したコンパイラパスの問題は、その VS Code プロセスから見える場所に対応するツールチェーンを移して解決しました。正確な原因や一般的な Store／MSIX 規則は未証明です。公開済みコンパイラのソースは `3901cf17` であり、バージョン番号が同じでも検証証拠は同一ではありません。0.2.3 では macOS／Linux のエディター操作と対話型 TUI 入力を再検証していません。インストール後にウィンドウを再読み込みし、**WBasic: Show Toolchain Status** で選択したコンパイラが 0.1.0 を示すことを確認します。`wbasic.compilerPath` を指定すれば、ポータブル ZIP のコンパイラを選べます。対応するランタイムとリンカーも同じパッケージのまま使います。Rust のソースや開発用インストールからコンパイラをビルドする場合は、ネイティブのツールチェーン／SDK が必要です。

## エディター機能とその境界

ライブ診断とナビゲーションは、未保存のソースを含むプロジェクトスナップショットを使います。補完は可視性を検査し、単純な宣言済みの受け手のフィールドやメソッドを、コンパイラのバインディング識別情報で解決します。ファイル間の名前変更は、変更後のスナップショットをコンパイラで検証します。カタログは **31 項目 / 10 カテゴリ / 61 教材ファイル**です。WORM M2/M3 はモジュールごとコピーでき、Check/Build に対応します。データベースの実行には明示的なパスが必要です。M4 UI はモジュールの準備が必要なリポジトリ内の参照資料で、Copy Example の対象外です。

任意の式の連鎖、型別名の完全な対応、組み込み String/Array メンバーの補完は未完成です。デバッグや整形は対応機能として掲げていません。公開済み 0.2.1 の統合では、ARM64 の各環境で **プロトコル 71 件**、**エディター 120 件**、**実際の VS Code Extension Host 11 件**が通り、Rust テストは Windows 519 件 / macOS 507 件が通りました。既存の opt-in の除外テストは別に扱います。リリースでは、対応するネイティブ release ビルドと、ZIP 展開後のテストを追加しています。過去の本の全サンプルを再実行したという意味ではありません。

## パッケージのインストールと確認

展開前に、ZIP の SHA-256 を対応するファイルとリリース記録に照合します。`Install-And-Test.ps1` または `Install-And-Test.sh` を実行し、セッション用 PATH ヘルパーを使います。基本のコンパイルに Node は不要です。Node はプロトコルアダプター用、VS Code はエディター利用時の任意の要素です。[入門]({{< relref "/books/getting-started/_index.md" >}})、[WORM SQLite]({{< relref "/books/standard-library/worm-sqlite.md" >}})、[拡張機能ガイド]({{< relref "/books/w-basic-extension/_index.md" >}}) を参照してください。

ネイティブの開発ホストでのパッケージ検証は、Windows 11 Pro 25H2 ARM64（PowerShell 5.1 と 7）、macOS 26.6.2 ARM64 を対象にしています。Unicode、コンパイル・実行・ビルド、ゼロ件でないテスト検出、請求額の検査が通っています。ただし、SDK のない新規マシンでの受け入れを証明するものではありません。再配布通知、署名・公証、本番利用の権限は未完了で、`noSdkDistribution` は false のままです。

## 受け入れと過去のサンプル

公開済み v0.1.0 の時点で、規範的な draft v0.3 のカタログは **72 Passed / 23 Planned / 0 Deferred** で、WORM の独立したマイルストーンは含みません。この数字は公開リリースの境界を示し、後続の開発ラウンドの評価や昇格を意味しません。R6 D1–D5 は記録された範囲で通っています。Windows OSC52 の成功確認には固定した非公開 Microsoft ConPTY 接続先を使い、一部の OS 同梱ホストでは依然としてタイムアウトします。NativeLocal と OSC52 は別経路です。Linux ARM64 とネイティブ x86_64 は、この公開リリースの検証証拠には含まれません。

小さな WBasic プロジェクトの本は、記録されたリビジョンで **ネイティブ検証済み 29 例 / 計画段階 52 教材**を保っています。このリリースによって、計画中の教材や、人間・AI のコストに関する主張が自動的に検証済みになることはありません。過去の証拠は元のバージョンとハッシュを保ち、現在の識別情報はリリース記録とサイトのマニフェストが示します。
