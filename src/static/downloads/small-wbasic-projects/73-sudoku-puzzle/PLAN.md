# แผนโครงการ 73: ตรวจหรือแก้ตารางซูโดกุ

สถานะ: `draft.wbas.txt` ผ่าน `wb check --json` ด้วย compiler ที่ตรึงไว้โดยไม่มี diagnostic; ยังไม่ผ่านการรัน native/เกณฑ์รับงาน และยังไม่มี `main.wbas`

เป้าหมายร่างนี้: ตรวจว่ากระดาน 9×9 บางส่วนไม่มีเลขขัดกติกา ไม่ตัดสินว่ามีคำตอบหรือไขเสร็จ
ข้อมูล: Array ซ้อนกัน, 0=ช่องว่าง, 1..9=ค่าที่ใส่, seen[1..9] สำหรับแต่ละกลุ่ม
วิธี: ตรวจขนาดกระดานก่อนอ่าน index; ตรวจแถว หลัก กล่อง 3×3 แยกกัน; 0 ข้ามได้, ค่านอกช่วงและเลขบวกซ้ำผิด
รอยเดินมือ: แถวแรก 5,3,0,0,7,0,0,0,0 ถูกกติกาในตัวเอง; เปลี่ยนช่อง (0,2) เป็น 5 แล้วชน seen[5]
เกณฑ์ที่ต้องตรวจ: Given กระดานตัวอย่าง Then ถูกกติกาบางส่วน; Given แถว/หลัก/กล่องมีเลขซ้ำ Then ผิด; Given แถวสั้นหรือค่า −1/10 Then ผิด; Given มีช่องว่าง Then อย่าบอกว่าไขเสร็จ
ตัวแก้เป็นแผน: เลือกช่อง 0 ลอง candidate 1..9 ที่ไม่ชนแถว/หลัก/กล่อง; recurse; ทางตันย้อนค่าเป็น 0; ไม่มีช่องว่างจึงพบหนึ่งคำตอบ; ถ้าจะพิสูจน์หนึ่งคำตอบ ให้นับจนถึง 2 แล้วหยุด
ตัวสร้างเป็นแผน: เริ่มกระดานเต็ม ลบช่องแล้วนับคำตอบหลังทุกครั้ง เก็บการลบเฉพาะเมื่อยังมีคำตอบเดียว; การสุ่มลำดับต้องกำหนด seed/ช่วงค่า PRNG; คำขอไลบรารีคือ SWP-FR-01 ไม่ใช่ API ที่ร่างใช้
งานค้าง: รันตัวตรวจบน native, solver กับกรณีไม่มี/หลายคำตอบ, ตัวสร้างที่พิสูจน์เอกลักษณ์ และ input; แบบฝึกหัดแรกคือ IsComplete แยกจาก ValidBoard
