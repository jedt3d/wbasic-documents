## Model, callbacks และ terminal

[counter-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/examples/r6/counter-terminal.wbas) ประกาศ `Counter` เป็น `Structure` และส่ง `Init`, `Update`, `View` ที่เป็น module-level procedures เข้า `Tui.Run(Of Counter)` `Init` ขอ focus ที่ปุ่ม `add`; `Update` รับ `Activate` เพื่อเพิ่มจำนวนและรับ `q` เพื่อ `Quit()`; `View` สร้าง `Tui.Text` กับ `Tui.Button` ใน `Tui.Column` ตามสถานะล่าสุด `Tui.Context Of Counter` ใช้ได้ใน callback ปัจจุบัน ไม่เก็บใน model หรือส่งเข้า worker

รันบน terminal จริงด้วย `wb run examples/r6/counter-terminal.wbas --runtime <matched-runtime>` กด Enter เพื่อเพิ่ม, กด `q` เพื่อออก โปรแกรมพิมพ์จำนวนสุดท้ายหลังคืน terminal แล้ว การรันนี้ต้องมี interactive TTY; redirected stdin/stdout ต้องรายงาน `Tui.NotInteractive` ไม่ใช้เป็นตัวตรวจอัตโนมัติของบท [R6 native terminal fixture](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/run-terminal-counter.wbas) และ ConPTY gate แยกตรวจ terminal lease, input และ recovery

## Capability snapshot และข้อความสำหรับทางออก CLI

`viewport.Capabilities` เป็น snapshot แบบอ่านอย่างเดียวของ endpoint, ขนาด, mouse, paste, focus, enhanced keys และการแสดงผล ค่าเริ่มต้นของ `Tui.Capabilities()` ระมัดระวัง: ไม่อ้างว่า terminal รองรับสิ่งที่ยังไม่ตรวจ แอปสามารถสร้าง snapshot ใหม่ด้วย `WithInput` และ `WithDisplay` แล้วส่งผ่าน `Tui.Options().WithCapabilities(...)`; [capabilities-headless.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/capabilities-headless.wbas) ตรวจค่า override และการเปลี่ยน viewport ใน fake session `WithProbeTimeout` จำกัดเวลารอคำตอบจาก terminal โดยรวม; การไม่ได้คำตอบให้ fallback แบบ conservative ไม่ใช่หลักฐานว่า terminal รองรับ protocol นั้น

เมื่อ stdin/stdout ไม่เป็น terminal แอปเลือกทางออกข้อความเองได้ด้วย `Tui.RenderText(view, width, profile)` โดยไม่เปิด terminal หรือส่ง escape sequences [render-text.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/render-text.wbas) ตรวจการตัดตามความกว้างเซลล์ของ `Unicode17Narrow` และ `Unicode17Wide` รวมถึง error ของ profile/width ที่ไม่ถูกต้อง นี่เป็น static rendering ของ view ไม่ใช่ `Tui.Run` แบบ interactive

## Fullscreen, Inline และ Static

`Tui.Options().WithMode(Tui.ScreenMode.Fullscreen)` ใช้พื้นที่เต็มหน้าจอ ส่วน `Inline` จอง live region ด้านล่างตาม `WithInlineHeight(rows)` โดยรักษา scrollback; `context.PrintAbove(text)` แทรกข้อความเหนือ region นั้นได้เฉพาะ Inline [modes-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/modes-terminal.wbas) เริ่ม Inline สูงสี่แถว ให้ปุ่ม `print` เพิ่ม `history-added`, แล้วใช้ `context.SetMode` สลับ Fullscreen กลับ Inline การสลับถูกคิวไว้หลัง callback และต้องรักษา model กับ focus เดิม [modes-resize.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/modes-resize.wbas) แยกขนาด terminal จริงใน `Resize` จาก `viewport.Height` ที่ถูกจำกัดไว้สี่แถว

`Tui.ScreenMode.Static` ผ่าน `Tui.Run` เรียก `Init` และ `View` อย่างละครั้งเพื่อเขียน snapshot เป็นข้อความธรรมดาโดยไม่เปิด raw mode หรือ event loop [modes-static.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/modes-static.wbas) แสดงผลและตรวจว่า timer, focus, PrintAbove และ SetMode ใน Static Init ได้ `Tui.InvalidPhase` [modes-invalid.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/modes-invalid.wbas) ตรวจ `WithInlineHeight(0)` เป็น `Tui.InvalidOptions`, PrintAbove ใน Fullscreen และ SetMode ไป Static เป็น `Tui.UnsupportedOperation` [modes-callback-error.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/modes-callback-error.wbas) ตรวจว่า PrintAbove ที่คิวไว้ก่อน callback ล้มเหลวไม่ถูกพิมพ์ออกมา Native mode gates บน Windows/macOS ARM64 ผ่านที่ checkpoint `32ecbdf`; Mac ยังทดสอบ resize ขนาด 0×0 ก่อนกลับเป็น 100×30 เพื่อยืนยันว่า loop ไม่หยุดหรือสร้าง viewport ขนาดผิด

`context.Log(Tui.LogLevel.Info, text)` ส่งข้อความไป sink ที่เลือกด้วย `Tui.Options().WithLogFile(path)` โดยไม่พิมพ์ทับ frame ไฟล์ log เปิดก่อนเปลี่ยน terminal mode และเพิ่ม record แบบ append; ข้อความหนึ่ง record อยู่หนึ่งบรรทัดในรูป `[Info] message` โดย control/newline ในข้อความถูกแสดงเป็นสัญลักษณ์ที่มองเห็น [logs-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/logs-terminal.wbas) รับ path จาก Main, log ตอน Init และก่อน Quit แล้วพิมพ์ผลหลังคืน terminal [logs-callback-error.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/logs-callback-error.wbas) ตรวจว่า record ที่คิวใน callback ซึ่งล้มเหลวไม่ลงไฟล์ ใน fake session ใช้ `session.LogLines()` อ่าน virtual transcript โดยไม่เปิด path ที่ตั้งไว้; [logs-headless.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/logs-headless.wbas) ใช้ path ที่ parent ไม่มีเพื่อตรวจลำดับและ rollback โดยไม่สร้างไฟล์ [logs-invalid.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/logs-invalid.wbas) ตรวจว่า Log โดยไม่มี sink ได้ `Tui.LogNotConfigured` และ Log ใน Static ได้ `Tui.InvalidPhase` Native log file/terminal gates ผ่านทั้ง Windows/macOS ARM64 ที่ source checkpoint `730992f`; หลักฐานแยกตาม host อยู่ใน round report

## ส่ง terminal ให้โปรแกรมภายนอก

`context.RunTerminalProcess(key, request)` เป็น effect จาก input ของผู้ใช้ `Tui.ProcessRequest(executable, arguments)` เก็บ executable และ argument array แยกกัน ไม่แปล shell syntax; `WithWorkingDirectory` และ `WithEnvironment` สร้าง request ใหม่ [process-headless.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/process-headless.wbas) ใช้ executable ที่ไม่มีจริงกับ `Tui.TestSession` เพื่อแสดงว่า fake session เพียงเก็บ `PendingProcesses()` ไม่ spawn child แอปเติม `CompleteProcess(key, 0)` หรือ nonzero exit และ `CompleteProcessWithError(key, error)` แล้วรับ `ProcessExited` ที่มี `RequestKey`, nullable `ExitCode` และ nullable `Error` โดยไม่เหมารวม nonzero เป็น error Error ที่ส่งเข้า fake completion ต้องถูกเก็บเป็นค่าเจ้าของของ session ไม่พึ่งอายุของตัวแปรต้นทาง; [process-rollback.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/process-rollback.wbas) ตรวจว่า callback ที่ throw หลัง queue request ทิ้ง effect และไม่ทิ้ง pending process ไว้ให้ Close dispatch ซ้ำ

บน terminal จริง [process-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/process-terminal.wbas) รับ endpoint, executable, script, child mode และ working directory จาก Main; key `e` ขอ handoff พร้อม environment override แล้ว parent หยุด paint/คืน terminal ก่อน child ใช้งาน เมื่อ child จบ parent reacquire และ render `parent:resumed` ก่อนรับ `q`; ผลสุดท้ายพิมพ์หลังคืน terminal [process-worker.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/process-worker.wbas) ให้ worker รอ marker จาก child, ตรวจว่าเขียน terminal ที่ถูก lease ไม่ได้, แล้วส่งผลกลับ UI หลัง reacquire Native PTY/ConPTY handoff gates ผ่านทั้ง Windows/macOS ARM64: child อ่าน terminal ได้, parent ไม่ paint แทรก, nonzero/signal/interrupt แยกผล, และ mode/ownership คืน กรณี Unix child ทิ้ง terminal mode ไว้ผิด parent คืน mode เดิมก่อน resume ทั้งสอง host ผ่าน failure hooks ของ process handoff แยกจาก normal path Mac full gate ใช้ `2d79bd5`; Windows full/affected gates ใช้ checkpoint ก่อนหน้าที่พฤติกรรม Windows ไม่เปลี่ยนใน Unix-only follow-up ดู [phase evidence](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/evidence/r6-process-handoff-2026-09-29.json) สำหรับ SHA และผลแยก host; final integrated gate ยังต้องใช้ SHA เดียวกัน

## พักและกลับเข้า terminal

`context.Suspend()` เป็น effect ที่ commit หลัง callback สำเร็จ; บน Unix แอปคืน mode ก่อนพักและเมื่อได้รับ SIGCONT จะ reacquire พร้อม full redraw บน Windows การเรียกนี้คืน `Tui.UnsupportedOperation` ให้แอปเลือกทางอื่น [suspend-headless.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/suspend-headless.wbas) ใช้ fake session ตรวจว่า `session.IsSuspended` เปลี่ยนหลัง `Step()`, key ที่ส่งระหว่างพักยังรออยู่ และ `session.Resume()` ส่ง `Event.Terminal.Kind="Resumed"` ก่อน key ที่ค้าง [suspend-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/suspend-terminal.wbas) แยก real Unix resume/resize กับ Windows unsupported path Native suspend gates ผ่านบน macOS ARM64 ห้ากรณีและ Windows ARM64 ทั้ง unsupported กับ second interrupt ที่ checkpoint `ab6f9bc`; ดู [phase evidence](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/evidence/r6-suspend-2026-09-29.json) สำหรับผลแยก host

## Clipboard แบบ explicit (T32 pending)

`Tui.Options().WithClipboard(readRoute, writeRoute, timeoutMs)` เลือกเส้นทางอ่านและเขียนแยกกันด้วย `Tui.ClipboardRoute.Disabled`, `NativeLocal` หรือ `OSC52`; ค่าเริ่มต้น Disabled ไม่อ่าน clipboard ระหว่าง probe หรือ View การตั้ง route เป็นเพียงนโยบายอนุญาต ไม่ยืนยันว่า provider หรือ terminal ปลายทางรองรับและทำงานสำเร็จ แอปขอ `context.ReadClipboard(key)` หรือ `context.WriteClipboard(key, text)` จาก callback ที่ผู้ใช้สั่งเท่านั้น ผลกลับมาใน `Event.Clipboard` ซึ่งมี `RequestKey`, `Operation`, nullable `Text` และ nullable `Error` การอ่านสำเร็จเป็นข้อความว่างมี `Text=Some("")`; failure มี `Text=Null` พร้อม Error จึงไม่ปนกัน การเขียน OSC52 สำเร็จหมายถึงส่ง bytes ให้ terminal แล้ว ไม่ใช่คำยืนยันว่า clipboard ของ OS เปลี่ยน

[clipboard-headless.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/clipboard-headless.wbas) ใช้ fake session ตรวจการอ่านค่าว่าง/ไทยกับ emoji, การเขียน และ error ทั้งสองทิศทาง `PendingClipboard()` กับ `CompleteClipboardRead/Write/WithError` ไม่แตะ clipboard จริง [clipboard-rollback.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/clipboard-rollback.wbas) ตรวจว่า callback ที่ล้มหลัง queue คำขอไม่เหลือ pending request ทั้งสองกรณีผ่าน native gate บน Windows/macOS ARM64 แล้ว [clipboard-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/clipboard-terminal.wbas) กับ [native harness](https://github.com/jedt3d/wbasic-language/blob/main/tools/native-conformance/r6_clipboard_native.py) ทดสอบ boundary โดยไม่อ่านหรือเขียน clipboard ของผู้ใช้จริง ที่ product revision `e39a31b` (fixture-only timeout revision `2856968`) macOS ARM64 ผ่าน 11 กรณีปกติทั้ง debug/release: OSC52 Unicode/empty/invalid/timeout/quit/write และ large write, Disabled, SSH denial และ production guards สองกรณี Private-provider hooks อีกสามกรณีผ่านด้วย named pasteboard: Unicode, empty และ Objective-C exception ที่แปลงเป็น Error ไม่ข้าม FFI Windows ARM64 ผ่านห้ากรณีปลอดภัยในแต่ละ profile: OSC52 read หมดเวลาแล้วคืน mode, Disabled, SSH denial และ production guards สองกรณี แต่ ConPTY บน host นี้ไม่ส่งต่อ OSC52 read query; จึงยังไม่พิสูจน์ read response และไม่เรียก OSC52 write test จนกว่าจะมี private clipboard isolation ของ ConPTY host การสร้าง private NativeLocal window station บน Windows ถูก process permissions ปฏิเสธ จึงยังไม่มี provider-success gate ที่ fixture revision `6a3938c` มี native pending-read disconnect case เพิ่มอีกหนึ่งกรณี ผ่านทั้ง debug/release บน Mac โดยปิด PTY หลังเห็น query และตรวจว่าออกภายในสามวินาทีด้วย `Tui.TerminalWrite`; ไม่อ้างว่าคืน modes ของ endpoint ที่ถูกทำลายแล้ว การคืน terminal ขณะ output worker ค้างใน kernel แบบไม่สิ้นสุดยังพิสูจน์ไม่ครบ T32 จึงยัง pending

ตาม [นโยบาย cleanup ของ terminal](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/wbasic-tui-spec-draft-0.3.md#1221-bounded-cleanup-when-output-remains-blocked) ถ้า OSC52 packet ส่งได้เพียงบางส่วนแล้ว output ค้างไม่สิ้นสุด `Tui.Run` ต้องหยุด dispatch, คืน OS input settings แบบ synchronous เท่าที่ host ทำได้ และคืน Error ภายในขอบเวลาที่กำหนด ไม่มี final model ที่สำเร็จ หากไม่มี Error เดิมให้ใช้ `Tui.ClipboardCleanupPending`; หากมี Error เดิม ให้คงเป็น primary แล้วแนบ cleanup error ใน `Suppressed` Runtime ต้องเก็บ writer, descriptor และตำแหน่ง byte ใน packet ด้วยทรัพยากร/queue ที่มีขอบ และถือ terminal lease จนส่งหรือยุติ packet นั้นก่อน restoration bytes และ cleanup จบ ระหว่างนั้น Core alias ที่ใช้ terminal เดียวกันและ TUI session ใหม่ต้องถูกปฏิเสธ; output ที่ redirect แยกยังอยู่ภายใต้กฎเดิม กรณี endpoint ยัง blocked หรือถูกทำลาย ห้ามอ้างว่า visual restoration เสร็จแล้ว นี่เป็นสัญญาที่อนุมัติสำหรับ error path; Mac partial-packet gate ผ่านแล้ว; full-output และ Windows private gate ยัง pending ใน T32

ที่ product revision `e16a412` และ fixture revision `59c7a28` Mac private PTY backpressure gate ของ OSC52 packet ที่ส่งได้บางส่วนผ่านใน 1067 ms: `Run` คืน Error ก่อนเริ่ม drain, คืน input settings, เก็บ lease เพื่อกัน Core alias/session ใหม่ และหลัง drain ส่ง terminator ก่อน restoration bytes แล้วปล่อย lease ให้ session ถัดไปได้ ผลนี้ไม่พิสูจน์ completed-packet output worker ที่ค้างแบบไม่สิ้นสุดหรือ ordinary frame paint ที่ blocked; Windows private ConPTY/NativeLocal ยังไม่มี gate เพราะสร้าง isolated WindowStation ไม่ได้ T32 จึงยัง pending

## Output ปกติที่หยุดรับข้อมูล (T24/T29 pending)

สัญญา [§12.2.1](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/wbasic-tui-spec-draft-0.3.md#1221-bounded-cleanup-when-output-remains-blocked) ครอบคลุม frame และ terminal-mode output ที่หยุดรับ bytes ด้วย รวมถึงก่อน frame แรกเสร็จ ถ้า foreground write ถึง deadline ให้รายงาน `Tui.TerminalWrite` และแนบ `Tui.TerminalCleanupPending` เมื่อยังถือ output cleanup; Error ของแอปที่เกิดก่อนยังเป็น primary ระหว่าง cleanup `Tui.Run` ใหม่ได้ `Tui.TerminalWorkerBusy` และ Core alias ของ terminal เดียวกันใช้ไม่ได้ Runtime ต้องเก็บ packet ที่ค้างกับ byte offset ตามจริง ส่งให้ครบก่อน mode restoration และไม่เริ่ม escape sequence ใหม่หรือแทรก writer อื่น การสลับ mode ที่คิวไว้ต้อง balance keyboard stack ครั้งเดียว

โดยทั่วไปต้องคืน OS input settings ก่อน bounded error return ถ้า Windows ConPTY host ที่ไม่ตอบสนองทำให้คำสั่งคืน input ค้างด้วย [ข้อยกเว้นที่ผู้ใช้อนุมัติ](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/rounds/R6-windows-conpty-stall.md) ให้คืน Error ในขอบเวลาที่กำหนดขณะ **ทั้ง input และ output cleanup ยัง pending** โดยยังถือ terminal lease และทรัพยากรแบบมีขอบจน cleanup ทั้งหมดเสร็จ ห้ามรายงานว่า input คืนแล้วก่อนสำเร็จจริง กฎนี้เป็นสัญญาที่อนุมัติ ยังไม่ใช่ผล native gate ที่ผ่าน

## เลือก terminal โดยไม่ปนกับ machine output

`Tui.Options().WithTerminal("StandardError")` ใช้ stdin ที่ interactive กับ stderr ที่เป็น terminal ทำให้ stdout ที่ถูก pipe เก็บ `PrintLn` สำหรับเครื่องอ่านได้ `"StandardIO"` ต้องมี stdin/stdout เป็น terminal; `"Auto"` ไม่ลัดข้าม stdin ที่เป็น pipe ทั้งสองกรณีที่ไม่ interactive คืน `Tui.NotInteractive` โดยไม่ส่ง escape จากโปรแกรม `"ControlTerminal"` เป็นการเลือก explicit: แอปเปิด controlling terminal แม้ stdin/stdout/stderr เป็น pipe และ capability view รายงาน `ControlTerminal:ControlTerminal` [endpoints-terminal.wbas](https://github.com/jedt3d/wbasic-language/blob/main/fixtures/source/r6/endpoints-terminal.wbas) พิมพ์ machine output ก่อน/หลัง session เพื่อให้ตรวจว่าไม่ปนกับ frame

Terminal session เช่า underlying terminal: `Console.Error.Flush()` ใน StandardError session ได้ `IO.StreamInUse` แต่ stdout ที่ pipe เมื่อเรียกใน UI callback ได้ `Tui.BlockingOperation` ControlTerminal ที่ stdio ทั้งหมดเป็น pipe ให้ `Tui.BlockingOperation` กับทั้ง stderr/stdout; เมื่อ stderr ยังชี้ terminal เดียวกันกับ ControlTerminal จะได้ `IO.StreamInUse` [native endpoint harness](https://github.com/jedt3d/wbasic-language/blob/main/tools/native-conformance/r6_endpoint_native.py) ตรวจ stdout exact, frame, restoration และ alias นี้บน Windows ARM64 ห้ากรณีกับ macOS ARM64 หกกรณี (Mac gate `e747e10`) บน Mac ถ้า stdin ชี้ PTY คนละตัวกับ controlling terminal ระบบคืน `Tui.UnsupportedTerminalRouting` ก่อนเปลี่ยน mode ของตัวที่ผิด; จึงยังไม่อ้างว่ารองรับ routing ไป arbitrary terminal macOS backend ใช้ `select` สำหรับ `/dev/tty` หลังพบว่า Darwin `poll` รายงาน `POLLNVAL` แม้ fd นั้นเขียนได้จริง

## File I/O ใน worker และการยกเลิก (T25 ผ่าน native gate ทั้งสอง host)

Worker เรียก `File.Open*`, `File.ReadBytes`, `File.WriteBytes` และ stream ที่มีไฟล์รองรับได้แบบ synchronous ตามเดิม แต่ runtime ส่ง native file call ไปยัง [file execution bridge](https://github.com/jedt3d/wbasic-language/blob/main/crates/wb-runtime/src/file_io_bridge.rs) ซึ่งมี backend คงที่สี่ thread และรับงานที่กำลังทำหรือรอรวมไม่เกินแปดงาน การรอของ worker มี deadline 30 วินาทีต่อ operation และตอบ cancellation โดยไม่รอให้ kernel call ที่ค้างจบ งานที่ค้างยังถือไฟล์และ buffer ของตัวเองจน backend จบ; stream เดิมไม่อนุญาต `Read`/`Write`/`Seek`/`Close` ซ้อนระหว่างนั้นและรายงาน `IO.StreamInUse` เมื่อปิด stream ที่ยัง busy จะปล่อย handle ของแอป แต่ backend ถือ native file ไว้จนจบ การเปิด TUI session ใหม่ต้องรอให้ backend และการปิดไฟล์ที่ค้าง drain ก่อน

Budget ของ bridge สำหรับข้อมูลที่งาน backend ถือรวมกันคือ 64 MiB; `File.WriteBytes` ใน worker จำกัดทั้งไฟล์ที่ 64 MiB ส่วน `File.ReadBytes` จำกัดจำนวน byte ตามขนาด `Value` ของ runtime เพื่อให้ array ของ byte ที่คืนมามี allocation ไม่เกิน budget 64 MiB ด้วย ทั้งคู่รายงาน `IO.PayloadLimit` เมื่อเกิน ขีดนี้แยกจาก `Jobs.PayloadLimit` ของ input/result และไม่เปลี่ยนการเรียกไฟล์แบบ synchronous ใน `Main` Cancellation รายงาน `Jobs.Cancelled`, deadline ได้ `IO.Timeout`, backend เต็มได้ `IO.TooManyOperations`; worker อ่าน `IO.Stdin` ไม่ได้และรับ `Jobs.UncancellableIO` งานที่ยังไม่เริ่มจะตรวจ token/deadline ก่อนเปิดหรือเขียนไฟล์ แต่งานที่เริ่มแล้วอาจสร้าง ตัดทอน หรือเขียนไฟล์สำเร็จหลังผู้ใช้ขอยกเลิก การยกเลิกไม่ย้อนผลข้างเคียงของไฟล์ แอปที่ต้องการเผยแพร่ผลเฉพาะเมื่อสำเร็จควรเขียนไฟล์ชั่วคราวแล้ว commit/rename ตาม API ที่ใช้

[stream tests](https://github.com/jedt3d/wbasic-language/blob/main/crates/wb-runtime/src/streams.rs) สี่กรณีกับ [bridge tests](https://github.com/jedt3d/wbasic-language/blob/main/crates/wb-runtime/src/file_io_bridge.rs) สามกรณี ตรวจ worker file calls, การปฏิเสธ stdin, cancellation/deadline, capacity, cursor quarantine, ช่วงว่างระหว่าง write chunks และการปิดไฟล์หลัง backend drain [HTTP cancellation tests](https://github.com/jedt3d/wbasic-language/blob/main/crates/wb-runtime/src/http.rs) และ [SQLite interruption test](https://github.com/jedt3d/wbasic-language/blob/main/crates/wb-runtime/src/sqlite.rs) ตรวจอีกสอง backend แยกกัน Rust tests เหล่านี้ผ่านแบบ native บน Windows/macOS ARM64; [worker file example](https://github.com/jedt3d/wbasic-language/blob/main/examples/r6-streaming/tail-worker-terminal.wbas) กับ native streaming gate ตรวจว่า WBasic source ใช้ worker/File ABI จริง หลักฐานสองชั้นนี้รองรับ T25 ที่ integrated product revision `e39a31b`; ตัวอย่าง WBasic ไม่ได้จำลองทุก blocked kernel call ซ้ำกับ barrier tests
