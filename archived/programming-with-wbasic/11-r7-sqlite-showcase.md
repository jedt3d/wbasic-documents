# 11. SQLite showcase: ตารางแบบ page, ฟอร์ม และงานเบื้องหลัง

**สถานะ:** project/headless/native ผ่านบน Windows และ macOS ARM64 ตาม [R7 report](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/rounds/R7-groups-7-8.md): product b07e4b6, Windows harness correction/performance 6ff461e. Visual/font acceptance ยังเป็น partial และ R6/R8 release blockers ยังเปิดอยู่ ผลนี้ไม่ใช่ clean-machine no-SDK package acceptance.

แอปตัวอย่างใช้ฐาน SQLite `customers` จริงใน workspace ชั่วคราว มีชื่อ เมือง และ note ที่มีภาษาไทย/emoji ผู้ใช้ browse, ค้นหา, เลือกแถว, แก้ชื่อ/เมือง/note, ดูสถิติ และส่งออก CSV ได้ `View` สร้าง Table กับ editor จาก model ที่มีอยู่เท่านั้น; มันไม่ query ฐานข้อมูลหรือ sort แถวระหว่าง paint ดังนั้น resize กับการวาดซ้ำไม่ทำให้ SQL ทำงานเพิ่มเอง

## ให้ worker ทำ I/O แล้วส่ง page กลับ

`ReadPage` ใน [Main.wbas](https://github.com/jedt3d/wbasic-language/blob/main/examples/r7-showcase/src/Main.wbas) เปิด `Sqlite.Connection` ด้วย `Using`, query count และแถวด้วย `Sqlite.BindString`/`BindInteger`, `LIMIT ? OFFSET ?` แล้วคืน `Result.Rows`, `First` และ `Total` ปุ่ม sort เลือกหนึ่งในสอง SQL statements คงที่ (`ORDER BY id` หรือ `ORDER BY name, id`); ชื่อ column ไม่ได้มาจาก user string งานนี้ตรวจ `job.CheckCancelled()` ก่อนและระหว่างอ่าน `RequestWork` จอง `Jobs.Start(Of Model, Request, Result)` และเก็บ `Jobs.Id?` ใน model ส่วน `Done` รับเฉพาะ id ที่ยัง active แล้วสร้าง `Tui.TablePage` จากแถวที่ได้ พร้อม `TableState.WithFirstRow` การเลื่อน page จาก `Tui.DataEvent.ProposedFirstRow` เป็นคำขอให้แอปเริ่มงานใหม่ ไม่ใช่คำสั่งให้ Table ไปอ่านฐานข้อมูลเอง

`Select` ใช้ stable row ID จาก `Tui.DataEvent.RowId` หา `Customer` ใน page ปัจจุบัน จากนั้นอัปเดต `TableState.WithSelectedId` และค่าของ editor ใน model ผู้ใช้แก้ text ผ่าน `Tui.TextInput.Update` แล้วกด Save; worker ส่ง `UPDATE customers SET ... WHERE id = ?` ที่ bind ค่า เมื่อสำเร็จจึงขอ page ใหม่ สถิติใช้ `count(*)` กับ `count(DISTINCT city)` ใน worker อีกชนิดหนึ่ง การค้นหาเป็น SQL ที่ bind pattern จาก text input; ถ้านำตัวอย่างไปใช้กับข้อมูลภายนอก ต้องตัดสินนโยบาย wildcard `%`/`_` ของ `LIKE` ให้ตรงกับ UX ที่ต้องการ

## Progress, cancel, error และ export

งาน export อ่าน SQLite cursor ตามลำดับ id และเขียน CSV ด้วย `Csv.Writer` ภายใน `Using` ลง path `.partial` เฉพาะ generation หลังปิด writer/cursor/connection และตรวจ cancellation อีกครั้ง worker จึงเรียก `File.Move(tempPath, exportPath)` เพื่อแทนที่ไฟล์ปลายทางใน directory เดียวกันแบบ atomic การย้ายนี้ไม่ใช่สัญญา fsync/durability งานรายงาน `Jobs.Progress` ระหว่างส่งออกและตรวจ cancellation ใน loop; callback อ่าน `Completed As Integer`, `Total As Integer?` และ `Message As String` โดยต้องตรวจ `Total` ว่าเป็น `Null` ก่อนใช้กับงานที่ยังไม่รู้จำนวนทั้งหมด status bar แสดงความคืบหน้าที่ callback เก็บไว้ ปุ่ม Cancel ส่ง `context.CancelJob(id)` สำหรับงาน active ปุ่ม Retry ใช้ request ล่าสุดแต่สร้าง temp path generation ใหม่ รหัส `Error.Code` ถูกเก็บใน status แทนการทำให้ View โยน error

การยกเลิกก่อน `File.Move` อาจเหลือไฟล์ `.partial` แต่จะไม่แทนที่ CSV ปลายทางเดิม; การยกเลิกที่แข่งกับขั้น commit ยังอาจเกิดหลังผลภายนอกสำเร็จ จึงต้องตรวจ path จริงเมื่อ retry หรือใช้งานต่อ การ cleanup ของ SQLite cursor/connection และ CSV writer เป็นงานของ `Using` ส่วน callback id check ป้องกัน completion เก่ามาแทนงานใหม่ใน model

## ทดลองและขอบเขตหลักฐาน

เปิด [Showcase.wproj](https://github.com/jedt3d/wbasic-language/blob/main/examples/r7-showcase/Showcase.wproj) ที่ประกาศ bundled Tui/Jobs/Sqlite/Csv และชี้ entry ไปยัง [Main.wbas](https://github.com/jedt3d/wbasic-language/blob/main/examples/r7-showcase/src/Main.wbas); saved-project metadata ตรวจผ่านหลังระบุ dependencies ครบ จาก repository root ให้รัน `python scripts/test-r7-showcase.py --source-only` สำหรับ project emit/source check เท่านั้น, `python scripts/test-r7-showcase.py` สำหรับ source check กับ deterministic headless scenario, และ `python scripts/test-r7-showcase.py --native` สำหรับ matched runtime, keyboard/terminal และ SQLite/CSV จริง คำสั่งสุดท้ายต้องมี compiler/static runtime ที่ build จาก source เดียวกันและ native ARM64 toolchain ของ host ผล native ผ่านบน Windows/macOS ARM64 ทั้งคู่ตาม round report ห้ามถือว่า project emit สำเร็จเท่ากับการรัน terminal, query SQLite จริง หรือการส่งออก CSV byte-for-byte ชุด acceptance แยก deterministic headless snapshot/replay ออกจาก ConPTY/PTY และ visual font observation บท [TDD chapter 11](../tdd-with-wbasic/11-r7-showcase-acceptance.md) อธิบายการตรวจแต่ละขอบ

กลุ่ม R7 ก่อนหน้ามี [paged-data/rich/doctor lessons](10-r7-data-rich-diagnostics.md) ที่ผ่าน automated gates แล้ว แต่การเห็น Thai marks, border และ emoji ถูกต้องบน font/terminal ที่ผู้ใช้เลือกต้องมี human observation ตาม [R7 groups 4–6 report](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/rounds/R7-groups-4-6.md) ส่วน R6 deferred blockers, Linux/x86_64 native matrix และ R8 clean-machine distribution ยังแยกจากผล showcase นี้
