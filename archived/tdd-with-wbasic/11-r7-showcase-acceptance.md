# 11. ทดสอบ SQLite showcase แบบ BDD และแยกหลักฐาน terminal

**สถานะ:** project/headless/native ผ่านบน Windows และ macOS ARM64 ตาม [R7 report](https://github.com/jedt3d/wbasic-language/blob/main/dev-docs/rounds/R7-groups-7-8.md): product b07e4b6, Windows harness correction/performance 6ff461e. Visual/font acceptance ยังเป็น partial และ R6/R8 release blockers ยังเปิดอยู่ ผลนี้ไม่ใช่ clean-machine no-SDK package acceptance.

## Red/Green ของ page และฟอร์ม

Given ฐาน SQLite ชั่วคราวที่มีลูกค้าชื่อไทย เมืองสองแห่ง และ note ที่มี comma, quote, newline; When เริ่มแอปและรับ page แรก; Then Table แสดง stable row IDs และ `Total` ที่ตรงกับ query จริง โดย View ไม่เปิด connection Given กดค้นหาและเลื่อน page; When worker คืน page ที่ตรง `ProposedFirstRow`; Then model เปลี่ยน `TablePage`/`TableState` หลัง completion เท่านั้น แถวเดิมต้องไม่ทับผลของงานใหม่

Given เลือกหนึ่งแถว; When แก้ชื่อ/เมือง/note ใน text inputs แล้ว Save; Then worker ใช้ parameterized `UPDATE`, completion ขอ page ใหม่, SQLite ที่เปิดตรวจได้ว่าแถวเดิมมีค่าที่แก้จริง และ selection ยังอ้าง ID เดิม Given ข้อมูลไม่ครบหรือไม่มีแถวที่เลือก; When Save; Then status แสดง validation โดยไม่ส่ง SQL UPDATE ผู้ทดสอบต้องแยก failure ของ compiler, assertion, timeout และ terminal process ออกจาก expected validation

## งาน export/cancel/retry ที่ขอบ I/O

Given แถวที่มี quote/comma/newline/Thai; When กด Export CSV; Then worker เขียน temp `.partial` รุ่นของงาน, ปิด writer แล้ว `File.Move` ไปยัง final path ใน directory เดียวกัน เปิด CSV เป็น UTF-8 ด้วย parser อิสระและเทียบลำดับ header/rows กับข้อความหลัง decode รวมถึง quote/comma/newline round trip พร้อมตรวจ progress/completion จริง การยืนยันรูปแบบ escaping ระดับ byte ต้องมี assertion แยกจาก semantic round trip Given cancel ระหว่าง cursor/writer; When worker สังเกต `CheckCancelled`; Then final CSV เดิมต้องยังอยู่, temp อาจเหลือ, final outcome ต้องมีเพียงครั้งเดียวและ UI รับ input/resize ต่อได้ หาก cancel แข่งกับ atomic move ผลภายนอกอาจเกิดก่อน callback; test ต้องตรวจ path จริงแทนสมมติ rollback

Given เปิดฐานไม่ได้หรือ worker คืน Error; When callback `Failed` ทำงาน; Then status เก็บ `Error.Code`, active ID ถูกเคลียร์, Retry เริ่ม request ล่าสุดด้วย generation ใหม่และ completion เก่าไม่ทับผลใหม่ งาน statistics ตรวจ `count(*)`/`count(DISTINCT city)` กับฐานที่ seed จริง ไม่ใช้ hard-coded View output เป็นหลักฐาน SQL

Native runner มีสองลำดับที่แยกกัน: ลำดับแรกส่ง keyboard เก้าช่วงเพื่อเลือก/แก้/บันทึกแถว ID 2, ค้นหา, browse, sort, statistics และจงใจทำให้ `File.Move` ล้มเหลวโดยให้ final path ใน workspace fixture เป็น directory ก่อนลบ directory แล้ว Retry มันเปิด SQLite/CSV ด้วย Python อิสระเพื่อตรวจผล ลำดับที่สองเพิ่มข้อมูลจนมี 100,003 แถว เริ่ม export, resize 80×24 เป็น 50×18 ระหว่าง worker ทำงาน แล้วส่ง Esc; assertion เทียบ bytes ของ CSV final กับฉบับที่เสร็จก่อนหน้าและตรวจ `.partial` ที่เหลือ กรณีนี้พิสูจน์ขอบ cancellation เฉพาะจังหวะที่ fixture ทำให้เกิด ไม่ใช่สัญญาว่าการยกเลิกทุกจังหวะย้อน side effect ได้

## Deterministic, native และ performance เป็นคนละ gate
